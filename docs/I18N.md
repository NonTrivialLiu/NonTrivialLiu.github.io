# 中英文内容维护

站点以英文为默认语言，英文在根路径，简体中文在 `/zh-cn/`。翻译分三层落地：正文按文件配对，界面词条走统一词典，稳定标识永不翻译。

```text
内容层   英文 Markdown ─┐
                        ├─ page_id / permalink 配对 ─ Polyglot ─  /  与  /zh-cn/
         简中 Markdown ─┘
界面层   _data/en/i18n.yml ─┐
                            ├─ {{ "key" | t }} ─ 薄模板覆盖（只改文字读取方式）
         _data/zh-cn/i18n.yml┘
稳定层   page_id、permalink、category、BibTeX key、资源路径 ─ 始终不翻译
```

## 内容配对

| 内容     | 英文源文件                     | 简中译文                             |
| -------- | ------------------------------ | ------------------------------------ |
| 页面     | `_pages/about.md`              | `_pages/zh-cn/about.md`              |
| 博客     | `_posts/2025-01-01-example.md` | `_posts/zh-cn/2025-01-01-example.md` |
| 项目     | `_projects/example.md`         | `_projects/zh-cn/example.md`         |
| 动态     | `_news/example.md`             | `_news/zh-cn/example.md`             |
| 课程     | `_teachings/example.md`        | `_teachings/zh-cn/example.md`        |
| 书评     | `_books/example.md`            | `_books/zh-cn/example.md`            |
| 简历数据 | `_data/cv.yml`                 | `_data/zh-cn/cv.yml`                 |
| 界面词条 | `_data/en/i18n.yml`            | `_data/zh-cn/i18n.yml`               |

> `_bibliography/`、图片、PDF、音视频、JavaScript 与 CSS 保持单份共享。URL slug 继续使用英文。

一对文件用 `page_id` 建立对应关系，并声明各自语言：

```yaml
# _pages/about.md
lang: en
page_id: about
permalink: /
```

```yaml
# _pages/zh-cn/about.md
lang: zh-cn
page_id: about
permalink: /
```

只翻译 `title`、`subtitle`、`description`、正文、图注、图片 `title` 与 `alt`、课程名与材料名；`layout`、`page_id`、`permalink`、分类键、BibTeX 键、资源路径、Liquid 标签、代码与公式保持原值。

演示内容按文档数量取舍，避免同一模板反复翻译：

- 同一模板下有多份文档的只保留一份译文：`_projects/` 九篇正文相同，只翻 `1_project.md`；`_news/` 三篇同为动态模板，只翻 `announcement_2.md`。被裁掉的条目不再声明 `lang` 与 `page_id`，中文站按英文原文回退。
- 一类只有一份文档的优先翻译：`_teachings/` 的两门课程已有译文；`_books/` 的书评仍走英文 fallback，待占位正文替换为真实内容后再建立译文。

两条容易踩空的规则：

1. **集合条目的译文要显式写出 `permalink`。** 项目、动态、课程的 URL 由文件路径生成，`_projects/zh-cn/example.md` 会被推导成 `/zh-cn/projects/zh-cn/example/`。在译文 front matter 里补上英文版同样的 `permalink`，才会落在 `/zh-cn/projects/example/`。
2. **博客首页不要写 `page_id`。** jekyll-paginate-v2 会复制该页生成分页页，共享 `page_id` 会让 Polyglot 把所有分页页当成同一篇，canonical 全部指向最后一页。博客首页靠两边相同的 `permalink: /blog/` 配对即可。

### 博客与 Distill

文章沿用相同日期与英文 slug，`page_id` 相同；Distill 的公式、引用、脚本与图表写法保持不变，只翻译 front matter 中可读字段与正文，`toc.name` 与翻译后的标题保持一致。

## 界面词条

模板只出现语义键，译文集中在词典里：

```liquid
{{ 'home.news' | t }}
{{ 'categories.' | append: category | t: category }}
```

`t` 由 `_plugins/al_i18n.rb` 提供，按「当前语言 → 英文 → 键名」的顺序取值，键名兜底能保证译文缺失时页面不会留空。第二个参数是可选的兜底值，供项目分类这类键集不固定的标签使用。

日期同样走词条：模板先 `{% assign date_long = 'date.long' | t %}`，再交给 `date` 过滤器。英文仍输出 `%B %d, %Y`，中文排成「2025 年 4 月 28 日」。Liquid 4 不支持在过滤器参数里再套过滤器，格式串必须先赋给变量；句末标点放在 `punctuation.period`，中文用全角句号。

词典里的 `config:` 一节覆盖 `_config.yml` 的站点文案（`description`、`contact_note`、`footer_text`、`blog_name`、`blog_description`），只对当前语言生效，英文仍读 `_config.yml`：

```yaml
# _data/zh-cn/i18n.yml
config:
  footer_text: 由 <a href="https://jekyllrb.com/">Jekyll</a> 与 al-folio 主题驱动。
```

构建时会比对两份词典的键集合；缺失、多余、空值或非字符串取值都会写进构建日志，`config:` 的类型与键名也会校验。设置 `AL_FOLIO_I18N_STRICT=1` 时，任何一项错误都会让构建失败。新增一门语言时，复制 `_data/zh-cn/i18n.yml` 到 `_data/<lang>/i18n.yml`，在 `_config.yml` 的 `languages` 与 `language_names` 里登记，再照同样方式建立 `_pages/<lang>/` 等目录。

新增或修改覆盖后运行：

```bash
bundle exec al-folio upgrade overrides accept --all
bundle exec al-folio upgrade overrides audit --fail-on-stale
```

第一条命令把当前覆盖登记进 `.al-folio-overrides.yml`，第二条确认覆盖与已安装 gem 的上游版本一致。将来 gem 升级时，审计会指出哪些上游模板发生了变化。这些覆盖是临时适配层，等 `al_folio_core` 提供官方翻译钩子后即可整体删除。

## 验证

```bash
docker compose exec -T jekyll bash test/integration_i18n.sh
docker compose exec -T jekyll bash test/integration_polyglot.sh
```

`integration_i18n.sh` 用严格模式构建并逐页核对中文标签，同时验证词典缺键会让校验失败；`integration_polyglot.sh` 覆盖配对页的 canonical、hreflang 与语言切换。

## 本地预览的坑

`jekyll serve --watch` 的重建循环与静态构建有两处不同，踩到时会以为翻译丢了：

1. **构建中途失败会污染语言目录。** Polyglot 把「当前语言写到哪里」记在 Site 实例上，只在整趟渲染跑完时才还原；某趟渲染抛错（典型是抓取外部 RSS 超时）时，`jekyll-watch` 继续用同一个 Site，下一次重建就从 `/zh-cn/` 开始写：英文页覆盖中文页，再套一层 `/zh-cn/zh-cn/`。`_plugins/polyglot_compat.rb` 用 `ensure` 保证每趟本地化渲染结束时还原目录与排除清单，`test/integration_i18n.sh` 有一条中断后重建的检查。目录被写脏时重启容器。
2. **`_config.yml` 里的演示 `external_sources` 会让每次构建联网。** 代理或网络不稳时，抓 Medium、Google Blog 的 RSS 会把构建进程带崩（日志里是 `SSL_connect ... unexpected eof while reading` 或 `Failed to open TCP connection`）。不需要这两篇演示文章时，把 `external_sources` 设为 `[]`，本地构建即可完全离线。

另外，改动 `_plugins/` 下的文件后需要重启容器才会生效，`--watch` 不重载插件。

浏览器手查仍然必要，重点确认中英文页面互相切换、中文页面出现 `hreflang="zh-cn"`、canonical 指向当前译文，以及图片、公式、引用与 Distill 图表加载正常：

```text
http://127.0.0.1:8080/
http://127.0.0.1:8080/zh-cn/
```

## 已知边界

内容仍为英文的部分，都是刻意保留或受第三方限制：

- 博客文章本体未翻译，中文站的文章列表与详情沿用英文原文；要翻译时按配对规则新建 `_posts/zh-cn/`。同一模板只翻一份的取舍见上文，未被翻译的项目与动态条目同样按英文回退。
- 搜索弹窗由 `al_search` 的 `ninja-keys` 组件渲染，占位符与页脚提示来自插件的 Ruby 标签与第三方脚本；giscus 与 disqus 的配置警告文本也在插件内部，模板层够不到。
- `_pages/plugins.md` 是 al-folio 自己的插件目录页（`nav: false`），保持英文。
- 标签（`display_tags`、文章 `tags`）与项目分类一样是数据键，显示名未进词典；需要中文化时按 `categories` 的做法补 `tags.<name>` 词条。
- `_books/` 书评正文仍是拉丁占位文本，因此中文站暂时回退英文原文；`_data/zh-cn/cv.yml` 的推荐人评语也保留占位文本，替换为真实内容后再翻译。
- 简历页的 PDF 下载按钮指向英文示例 PDF；准备好中文 PDF 后改 `_pages/zh-cn/cv.md` 的 `cv_pdf` 即可。
